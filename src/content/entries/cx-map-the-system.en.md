## Principle

Before restructuring a tool, map the system it sits in. Each stage of the customer journey, which tools act at that stage, which actions fire, and how the stages connect, including the direction of each relationship.

## Why it matters

Working inside a tool makes you blind to what is not in it. An entire channel can be running elsewhere, on a separate inbox or a parallel process, and it stays invisible for as long as you only look from the inside. The map is what surfaces it. It also turns a restructure from a cleanup into a decision about where data should live.

## How to apply it

- Lay out the journey stages first, then attach tools and actions to each one.
- Draw the relationships and their direction, not only the inventory. The arrows carry more information than the boxes.
- Look for stages with no tool attached, and for customer interactions handled outside every system on the map.
- Treat any interaction landing outside the primary system as a silo to close rather than an exception to tolerate.

## Point of caution

This map ages with the tools and the journey it describes. A stale version invites decisions based on a system that no longer exists, so date it and treat it as a snapshot.
